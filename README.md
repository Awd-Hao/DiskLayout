# DiskLayout

按真实读取顺序重排文件在机械硬盘上的物理位置，让磁头顺着扫过去而不是来回跳。

只改数据块放在哪 —— 文件内容、路径、大小、时间戳都不变。

免安装，解压即用。需要 **Windows 64 位**；双击会弹一次 UAC（要直接对磁盘下指令）。

> ⚠️ **注意：它会直接搬动磁盘上的数据块。任何硬盘操作都存在风险，可能导致文件丢失、文件损坏、甚至硬盘损伤。使用本软件之前务必备份重要资料**

---

## 适合什么

**先说清楚：这是个使用范围很窄的工具。** 四条都满足才有收益，缺一条基本白做。

判断标准：

1. 读多写少
2. 会重复发生（读取）的
3. 每次读的东西和顺序基本固定
4. 时间花在寻道上（文件小、碎、散）

| 情况 | 结论 |
|---|---|
| 机械盘 + 一次加载读几千个小文件 + 会反复进 | ✅ 值得试（实测 1%～25%） |
| 机械盘 + 打包良好（平均文件 > 5 MB） | ⚠️ 常见 0%～2%，不值得 |
| 固态盘 | ❌ 无寻道，重排无意义（工具会拦） |
| 叠瓦盘 SMR | ❌ 随机写极慢，几乎无收益 |
| RAID / Storage Spaces / 网络盘 | ❌ 未验证，地址是虚拟的，前提不成立 |
| 移动硬盘 / U 盘 | ❌ USB 延迟主导，与布局无关 |
| 联机游戏 / 自动更新的软件 | ⚠️ 谨慎：反作弊可能介意，更新会打乱布局 |

工具自带诊断：「快速扫描」十几秒给出形态判断，「分析」实测能快多少。

---

## 两个"段"不是一回事

- **段（录制段）**：一次加载过程（启动 / 进关卡…）。历史记录里的"2 段"指这个。
- **块（文件碎片）**：一个文件在盘上被切成几块。"碎成 3 块"指这个。

**断点**：相邻两块不挨着才算一次；正好接上的不算。

## 它不是碎片整理

| | Windows 碎片整理 | DiskLayout |
|---|---|---|
| 目标 | 让每个文件连续 | 连续 **+ 按读取顺序排列** |
| 依据 | 文件大小 / 碎片数 | 录制的真实读取顺序 |
| 做完再跑对方 | 顺序被打回原样 | 连续性保留，顺序没了 |

**两者互斥。** 只在乎"文件别碎"的话，用系统自带的就够。

## 使用

1. 双击 `DiskLayout.exe` → UAC 里点「是」（清单已声明需要管理员，双击就会申请）
2. 「浏览...」选中程序总文件夹（不是子目录）
3. 重启程序 →「开始录制」→ 进主界面停 5 秒 →「✂ 在此切分」→ 打开要优化的内容 →「■ 停止录制」
4. 选中那一段 →「分析」→ 看百分比
5. 值得做 →「重排」

**录制前最好重启一次**（清系统缓存，否则部分读取不进记录）。
工具启动时会检查「快速启动」状态并提示该关机还是该重启。

## 功能

| 分类 | 功能 |
|---|---|
| 录制 | 开始 / 停止 / 在此切分 / 接着录 / 自动分段 |
| 分析 | 单段 / 批量 / 瓶颈诊断（给出 MB/s 与"是不是磁盘的锅"） |
| 排布 | 重排（一段排成连续）/ 全局优化（多场景共用一套布局）/ 填到前部（整个文件夹挪到盘头） |
| 空间 | 分布图（标位置）/ 内迁冷数据（挪内圈） |
| 碎片 | 快速扫描（形态判断 + 理论上限）/ 整理碎片（真实断点 ≥ 2 处搬成连续） |
| 维护 | 漂移检测 / 回滚（按清单搬回）/ 历史记录 / 两次录制对比 |

三个排布按钮的区别：

- **重排** — 把一段按录制顺序排成连续的一长条（要求有一块连续空闲区）
- **全局优化** — 启动、关卡、主城等场景共用一套布局，排一次全部受益（但单个场景的提升会被摊薄）
- **填到前部** — 不管顺序，整个文件夹挪到磁盘最前面（外圈最快）

前两个解决「顺序」，第三个解决「位置」，互相不替代。

## 实测

一台西数 500 GB 机械盘（格式化后 465 GB），两例，仅代表个例：

| 场景 | 统计口径 | 读取规模 | 结果 |
|---|---|---|---|
| 某二次元 PC 游戏 | 一次完整会话 | 1,972 个 / 3,513.8 MB | 省 25.2% |
| 某独立 UE 游戏 | 单个关卡加载 | 406 个 / 约 2.4 GB | 省 1.7% |

**两例变量可能不同，不能直接对比**，只能说明收益方差很大 —— 所以必须先测。

「省 25.2%」= 同一批文件按录制顺序读累计 354.5 秒，按物理顺序读 265.2 秒。
这是整场会话里所有读取的累加，不是一次启动的时间。

同一块盘：外圈顺序读 122 MB/s，内圈 62 MB/s，随机 4K 6~7 ms。

## 注意事项

1. **别让 Windows 自动碎片整理跑** —— 会打乱排好的顺序（界面有开关）
2. **不要把程序放在「下载」文件夹里** —— 在 `C:\Users\...\Downloads\...` 下运行会有两层问题：
   ① 每次启动都弹「打开文件 - 安全警告 / 无法验证发布者」**（和签名无关，是"下载目录"这个位置触发的）**
   ② 系统会拒绝程序打开磁盘卷（错误码 5），搬移功能全部失效

   **放到 `C:\` 或 `D:\` 下（例如 `C:\DiskLayout\`）就都正常了。**
2. **程序本体建议放固态盘** —— 历史、清单、日志都写在 exe 旁边的 `data\`
3. **搬移前先关程序** —— 文件被占用会跳过
4. **先备份** —— 任何磁盘操作都有风险
5. **联机游戏先确认反作弊政策**

**「填到前部」**：把整个文件夹挪到**当前位置之前的第一块连续空闲区**。
只用一整块，0 次额外跳转；**不拼空洞、也不往后面挪**。
前面没有装得下的整块空位时，这次就不做（会提示原因），不会拆成小块硬塞。

**「重排」**：它找一块 ≥ 整段大小的连续空闲区整段搬过去，不是原地调整。
若目标位置比当前靠内圈 10% 以上会先警告。

搬移时整个文件一次性移入连续区，所以碎掉的文件会被顺带捋顺（变成 1 段）。

## 已验证 / 未验证

**已验证**：Windows 10 22H2 64 位、NTFS、单个3.5寸 7200RPM CMR机械盘、4 KB 簇、单块盘。

**未验证**：Windows 7/8/11、32 位系统、SMR、RAID、Storage Spaces、ReFS、exFAT、
簇大小 ≠ 4 KB、动态磁盘、多盘卷。

理论上 .NET 4.0 自带于 Windows 7 起，程序为 x64 编译，Win7 64 位以上应该能启动。

## 常见问题

**会不会损坏文件？** 不改内容，只搬数据块并改映射表。每次搬移是 NTFS 的一个事务，完成或回滚。

**断电呢？** 可能停在两个文件之间：已搬完的在新位置，没搬的在老位置，每个文件本身完整；
布局只搬了一半，可用「漂移检测」看进度再跑一次。

**要重装或校验吗？** 不需要。路径、大小、时间戳、内容都没变。

**为什么我的只有 1%？** 读取顺序本来就接近物理顺序，或文件太大把寻道摊薄了。

**能撤销吗？** 能。每次搬移写 `*.manifest.csv`，「回滚」按清单搬回。

**进度条为什么卡几十秒？** 搬一个文件是一次系统调用，中途没有回调。这是接口限制。
